## 3. 对战美术方案
**资源分层**：T0 已有（20 种毛色小猫、30 种鱼图标，卡片式显示）→ **T1 Zoonami（第一批主力）** → T2 Tuxemon Set 1（第二批，要"素材致谢"面板，注意 ShareAlike）→ T3 新画（鸟、松鼠、山海经异兽）。
**规格**：战斗图 64×64（正/背）；队伍/背包头像 24×24（由战斗图缩小生成）；图标 16×16 沿用现有管线；构建时由 `tools/` 读取 `data/mons/art/` 生成图集；页面里一律**整数倍放大 + `image-rendering: pixelated`**。
**布局**：有背面图的用"对手右上（正面）、己方左下（背面）"；只有正面的（鱼系图标、Openmon）用面对面的对峙卡片布局。
**动画不用逐帧，全用变换**：入场滑入、攻击前冲、受击闪白+抖动、倒下下沉淡出、升级闪光、捕捉晃三下；技能特效用元素色粒子（见 §4.1 的颜色）。
**异色**：Zoonami 每只自带备用配色 → "异色精灵"，遇敌 1/64（可调），图鉴单独记录。
**造型风险**：CC0 只是作者对自己作品的授权，不能为"造型恰好像某个官方角色"免责。联系表里有几只橙色小恐龙（#23、#34）一类，造型容易让人联想到官方角色，**第一版不选**。
**命名**：Zoonami 怪物只有编号，名字由我们起（见 §5）。

## 4. 对战规则（宝可梦式，自拟数值，以下是设计，不是已验证的平衡）

### 4.1 元素：采用 18 属性相克表（主人 2026-11-04 决定）
- **表**：`data/mons/typechart-18.json`，来自 Pokémon Showdown `data/typechart.ts`（MIT）；属性相克是游戏机制，这里只存倍率。51 条克制、8 条免疫（测试核对）。
- **开放包**：`data/mons/packs/open/elements.json` = 同一张表 + 每种属性的显示颜色；徽章用汉字（不能只靠颜色）。
- **规则**：一只精灵 1~2 个属性，倍率相乘（×4 ~ ×0 ）；同属技能加成 ×1.5；"一般"是没有克制关系的基础属性。
- **之前的 13 元素自拟表**（金木水火土雷冰风毒光影星普通）已放弃；以后想加校园特色元素（学/乐/食）再单独设计。

### 4.2 六维与成长
**六维**：生命、攻击、防御、特攻、特防、速度（与图鉴素材的种族值一致）。技能分物理/特殊：物理用攻击 vs 防御，特殊用特攻 vs 特防。个体值 0–31；第一版不做性格；`stat = ⌊(2×种族值+个体值)×L÷100⌋+5`，生命再加 `L+5`。
**经验**：升到 L 级需要 L³；战斗经验 = 对手基础经验 × 对手等级 ÷ 7，没出战的队友一半（Monster Tamer 的公开思路）。升级学新技能，满 4 个时选择替换。第一版等级上限 20。

### 4.3 战斗
**伤害**：`(⌊(⌊2L/5+2⌋×威力×攻÷防)÷50⌋+2) × 暴击(1.5) × 随机(0.85~1) × 同属(1.5) × 元素倍率`；免疫为 0，否则至少 1；暴击 1/16；命中率按技能给定。同级同能力互打平均 3~9 回合（测试里蒙特卡洛检查）。
**行动顺序**：速度高先手，同速随机；技能预留 `priority`。
**PP 与回复**：技能带 PP；战斗外**坐在长椅上休息几秒**（服务器检查真的坐着，沿用"坐下"系统）→ 队伍 HP 与 PP 回满，不用新建医院地标；血量也随时间慢慢回（约 10 分钟，按时间戳懒计算）。
**异常状态**：睡眠/灼烧/中毒放第二批，第一版只留字段。
**捕捉**：`成功率 = clamp(物种捕捉率 ×(1.8−1.2×血量比)× 道具倍率 × 随机(0.9~1.15), 3%, 90%)`，服务器掷一次，客户端演"晃三下"；**道具无论成败都消耗**；对手是别人的精灵时不能捕捉。
**逃跑与全灭**：逃跑看速度差；全灭 → 回出生点附近、HP 回一半，不掉币不掉精灵。
**遭遇表**：直接复用 `fishing.ts` 写法（权重 + 昼夜/雨天/季节倍率 + 稀有度）；野生等级区间按生态区。
**回合协议**（服务器权威）：`遭遇提示 → 开战 → (选择 → 结算 → 事件列表)* → 结束{胜/负/收服/逃跑}`；每场有 `bid` 与回合号，只收当前回合，30 秒超时自动逃跑，结算幂等；事件用文字 key + 参数。
**可复盘**：服务器记录每场的（随机种子 + 行动序列），能重放，用于查投诉与作弊。
**预留**：亲密度字段；3 对 3、装备/能力盘；数码兽式照料与分支进化——都不进第一版。
