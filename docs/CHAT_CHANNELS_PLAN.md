# 聊天频道系统 方案（2026-11-05，设计稿，还没写代码）

> 目标：把现在"只有一个公屏"的聊天，升级成**多频道**——世界 / 附近 / 队伍 / 自建群聊 / 系统，可以和朋友组队聊天、拉群，玩家能**切换频道、开关频道、静音、管理群**，管理员能**监管**。
> 这份文档只是方案；末尾「需要你拍板的事」定下来后再开工。客户端 / 共享协议部分协作者也可以认领，服务端部分由主人实现（服务端不在公开仓库里，见 [COLLABORATION.md](COLLABORATION.md)）。

## 1. 现状（做方案前盘点的）

| 现有的 | 说明 |
|---|---|
| **公屏** | 一个频道，**跟着"世界"走**：公共世界 = 所有人、个人世界 = 只回显给自己、好友世界 = 房主 + 受邀好友。消息有记录编号 `mid`，永久写进服务器记录，管理员可查可撤回；进游戏时发最近 100 条公共世界的历史。 |
| **私聊** | 只能和好友，在「好友」窗口里，离线存、未读角标、可导出，服务器永久保存，管理员查看要写审计。 |
| **队伍** | 最多 4 人，成员必须互为好友，只在内存里（掉线就退）；现在**没有队伍聊天**。 |
| **过滤 / 风控** | 所有文字先过服务器的 `screen()`（敏感词打码/拦截/累计禁言）；`mu` 禁言对公屏、私聊、留言全都有效；管理员能"关闭公屏"（只影响公共世界）；玩家能举报每一条公屏消息。 |
| **界面** | 右下角一个小框（手机是点「聊天」展开），一个输入框；系统提示、好友提示、公屏话混在一起。 |

**缺的**：没法分开"闲聊"和"和朋友说话"；队伍/好友世界没有专属说话的地方；吵的时候没法关掉公屏；系统提示淹在聊天里。

## 2. 频道模型

一条消息永远属于**一个频道**，频道决定"谁能收到、存不存、怎么管"。

| 频道 | id | 谁收得到 | 存不存 | 谁创建 | 默认 |
|---|---|---|---|---|---|
| 🌍 **世界** | `world` | **当前世界里的所有人**（和现在的公屏完全一样：公共世界所有人 / 个人世界只有自己 / 好友世界成员） | 公共世界永久存，新玩家看最近 100 条 | 系统 | 开 |
| 📍 **附近** | `near` | 同一世界里、**视野范围内**的人（用现有的视野判断） | 只存管理员证据日志，不给玩家历史 | 系统 | 开 |
| 👥 **队伍** | `party` | 当前队伍的成员（≤ 4，自动出现，队伍解散就消失） | 内存里留最近一段；证据日志照存 | 系统（组队时自动） | 开 |
| 💬 **群聊** | `grp:<群号>` | 群成员（好友之间，见 §5） | **持久**：群信息 + 聊天记录，成员能翻历史 | 玩家 | 开 |
| 🎓 **年级**（可选） | `year:2024` | 同年级所有人（年级来自学生证，是固定选项，不能乱填） | 只留最近一段 | 系统 | 关 |
| 🔔 **系统** | `sys` | 只有自己 | 不存 | 系统 | 开 |
| ✉ **私聊** | `dm:<uid>` | 好友一对一 | 沿用现有的私聊存储 | — | 开 |

- **学院频道不做**：学院是玩家自由填写的文字，做成频道会被乱填、刷出一堆垃圾频道；年级是固定选项，才适合做自动频道。
- **世界频道 ≠ 群聊**：好友世界是"一起玩的空间"（房主解散就没了、只能在同一个世界里说话）；群聊是"一直都在的聊天室"（不管你们在哪个世界、在不在线都能聊、有历史）。两者不冲突：好友世界里说话走「世界」，拉群聊天走「群聊」。
- **个人世界里**：世界频道还是只回显给自己；**队伍 / 群聊 / 私聊仍然能收发**（它们本来就是好友之间的，不会破坏"安静一个人玩"）。
- 私聊先**保持在好友窗口里**不动，只是在聊天窗口的频道条里也能看到私聊的未读（点一下跳到好友窗口对应会话）；全部并进同一个窗口放到最后一期做。

## 3. 玩家怎么用（设置与发送）

**每个频道玩家自己有三个开关**（存在玩家档案里，换设备也在）：
- **开 / 关**：关了 = **服务器不再给你发这个频道的消息**（省流量），也不能在里面发言；打开时可以补看最近几条。
- **静音**：还收消息，但不弹小条、不冒气泡、不响提示，只在频道标签上留一个未读数——适合"想知道但别打扰我"。
- **置顶 / 排序**：常用频道排前面（可选，放最后）。

**发送**：当前选中的频道标签就是发送目标；也可以输入前缀临时发到别处：`/w 内容` 世界、`/n` 附近、`/p` 队伍、`/g 群名 内容` 群聊、`/y` 年级。在**已关闭**的频道里发言会提示"先把这个频道打开"。离线单机模式只有「世界」一个频道（只回显自己，和现在一样）。

**屏蔽**：被我屏蔽的人，他的话在**所有频道**里对我都不显示（服务器发之前就按接收人过滤，不是客户端藏）。

**头顶气泡**：世界、附近的话冒气泡；队伍的话冒一个不同颜色的小气泡（只队友看得到）；群聊不冒气泡。

## 4. 界面

**聊天窗口加频道条**：窗口顶部一排标签 `🌍世界 | 📍附近 | 👥队伍 | 💬学习群 | 🔔系统 ⚙`，每个标签有未读小红点/数字；点标签切换，当前标签就是发送目标；消息行前面带小色块标出频道（队伍绿、群聊蓝、系统灰…）。
- **⚙ 频道管理**（弹出面板）：列出所有频道，每行三个开关（开/关、静音、置顶），底部「新建群聊」「处理入群邀请」。
- **群设置**（群聊标签里的 ⋯）：成员名单、邀请好友、改群名、群公告、禁言成员、请出成员、退出群 / 解散群（权限见 §5）。
- **好友窗口**：新增「建群聊」（勾选几位好友一起建）、每位好友的操作里可以「拉进群」；队伍面板里加「队伍聊天」直达。
- **手机**：频道条横向滑动；竖屏聊天框展开时标签在顶；**横屏聊天框在屏幕顶部**（沿用 2026-11-05 的横屏适配，避开软键盘）；收起时左上角冒出的小条只显示"开着且没静音"的频道，并带频道色块。
- 快捷键（电脑）：`Enter` 聊天，`Tab` 在输入框里循环切频道，`Esc` 退出输入。

## 5. 群聊规则（建议值，可调）

| 项 | 建议 |
|---|---|
| 怎么进群 | **只能由群里的人邀请自己的好友**，对方在邀请条上点「接受」才进（60 秒有效，和组队一样）；**P2 不做公开搜索、不做邀请码**——防陌生人骚扰。以后想要再加「邀请码 / 申请入群」。 |
| 规模 | 每个群最多 **20 人**；每人最多**建 3 个**、最多**加入 10 个**；群名 ≤ 10 个字（过敏感词） |
| 角色 | **群主**（创建者）、**管理员**（群主指定，最多 3 个）、**成员**。群主：改名、设公告、任命/撤销管理员、请出任何人、解散、转让群主；管理员：请出成员、禁言成员（≤ 1 天）、邀请；成员：发言、邀请（群主可以设成"只有管理员能邀请"）、退出 |
| 群主离开 | 必须先**转让**；没有别人就只能**解散**；掉线不算离开 |
| 历史 | 新成员**只能看到加入之后的消息**；老成员可以向上翻历史；记录永久存在服务器（管理员可查，见 §7） |
| 被屏蔽 / 删好友 | 被我屏蔽的人不能再邀请我进群；我删了某个好友，不影响我们共同所在的群（群是独立的），但他不能再邀请我 |
| 拉人进群的限频 | 邀请要限频、一人同时只能有少量未处理的邀请，防止批量骚扰（具体参数不写在公开文档里） |

## 6. 协议与服务端设计

### 6.1 协议（`src/shared/protocol.ts` 只增不改；**协议版本 +1**，旧页面会被要求刷新一次，避免队伍/群聊的话漏进老页面的公屏）
**客户端 → 服务器**
- `chat {text, ch?}`：`ch` 不写 = `world`（兼容现有逻辑）。
- `ch_get`：要我的频道列表和设置。
- `ch_set {ch, on?, mute?, pin?}`：改某个频道的开关/静音/置顶。
- `ch_read {ch, upto}`：标记已读到哪一条（`mid`）。
- `ch_history {ch, before?}`：翻历史（群聊 / 队伍 / 世界）。
- 群：`grp_create {name, invite[]}`、`grp_invite {ch, uid}`、`grp_reply {gid, accept}`、`grp_leave {ch}`、`grp_kick {ch, uid}`、`grp_rename {ch, name}`、`grp_notice {ch, text}`、`grp_mute {ch, uid, min}`、`grp_role {ch, uid, admin}`、`grp_transfer {ch, uid}`、`grp_disband {ch}`。
**服务器 → 客户端**
- `chat` 增加 `ch` 字段（以及 `mid` 在各频道内的编号）；`chat_history` 增加 `ch`。
- `channels {items}`：我的所有频道（id、名字、类型、人数、我的开关、未读数、我的角色）；变化时增量更新 `channel_upd`。
- `grp_invite_ask {gid, name, from}`（入群邀请条）、`grp_event {ch, kind, ...}`（有人加入/退出/被请出/改名/公告/禁言，同时在群里生成一条系统消息）、`ch_result {ok, msg}`。

### 6.2 服务端怎么改
- **发送出口统一**：现在 `onChat` 直接 `sendWorld(p.w, chat)`。改成 `onChat(p, text, ch)`：先过**共同的检查**（隐身、禁言、限频、`screen()` 敏感词），再按频道**解析接收人**——`world` = 世界成员、`near` = 视野内的人、`party` = 队伍成员、`grp:*` = 在线的群成员——然后**逐个接收人过滤**（该频道对他"关"了的不发；他屏蔽了发言人的不发；他在群里被禁言不影响他收）。
- **新增 `server/channels.ts`**（群聊管理）：群的元数据 `channels.json`（防抖原子写，和玩家档案同一套）、群聊记录 `chmsg.jsonl`（追加写，沿用 `ChatLog` 的做法：每条有群内编号、撤回追加一行），邀请的内存状态；队伍的话也写进同一个记录文件（带 `ch: party:<id>`），**只当管理员证据，不给玩家历史**。
- **玩家档案**加 `Saved.ch`：`{ <频道 id>: { off?, mute?, pin?, read? } }`；世界/附近/队伍/系统这些"系统频道"的开关也存这里；老档案没有这个字段 = 全部默认。
- **全局规则继续有效**：`mu` 禁言管**所有频道**；"关闭公屏"开关只管 `world`（公共世界）和 `near`；隐身的管理员不能发言。
- **敏感词**：群名、群公告、群聊消息都走 `screen()`；严重违规的累计禁言规则不变。
- **世界切换**：`world` / `near` 频道随世界变（和现在一样，切世界会清空公屏）；`party` / `grp` 不受世界影响。

## 7. 管理与风控

**玩家自己管**：开/关、静音、屏蔽（全频道）、举报（每条别人的消息旁的 ⚑，所有频道一样）、退群。**群主/管理员管群**：见 §5。

**举报**：`report` 的 `kind: 'chat'` 加 `ch`；举报时服务器存**被举报的话 + 上下文 + 频道 + 群名/成员名单**，之后撤回了管理员还能看；群聊举报不暴露整段聊天记录，和私聊举报一样只留那一小段。

**管理员（站长 / 协管员）**：
- 管理面板「公屏记录」页加**频道筛选**（世界 / 附近 / 队伍 / 某个群）；撤回对所有频道有效（撤回后群里该条变灰字）。
- 新增「**群聊**」页：按群名 / 群号 / 成员校园号搜群；看成员和群公告；**解散群**、**改群名**（违规群名）、**禁言整个群**、把某人**移出**群。
- **看群聊记录属于隐私操作**（和私聊同级）：**站长**可以查，**每次查看写进「操作记录」**；**协管员默认只能看到举报里附带的证据**，不能随便翻群聊（权限表里加 `ch_log` 为站长专属，和 `log_dm` 一样）。玩家在群里能看到一行提示"🔒 群聊记录保存在服务器上，被举报或违规时管理员会查看"。
- 玩家档案页（上一期做的）里加一个「所在群聊」列表。

**滥用的防线**：群数量 / 规模限制、邀请限频、只有好友能互相拉群、公开搜索暂不做、群名和公告过滤、被举报多的群自动标红给管理员、违规禁言（`mu`）全频道通用。

## 9. 测试计划
- **共享纯函数**：频道 id 的解析/校验、前缀命令解析（`/p 你好` → `party` + `你好`）、群名/公告清洗。
- **服务端集成**（起真服务器 + ws 客户端，主人本机跑）：各频道只发给该收到的人（世界隔离、队伍成员、群成员）；关闭频道后收不到也发不出去；静音只影响未读数；屏蔽的人的话在所有频道都不下发；禁言对所有频道生效、"关闭公屏"只影响世界；群聊的建/邀请/接受/拒绝/过期/满员/退出/转让/解散；群聊记录持久化（重启还在）、撤回、新成员只看到加入之后的；举报带频道和证据；管理员权限表（协管员不能翻群聊）；老档案没有 `Saved.ch` 也正常。
- **客户端**：频道条切换、未读数、`/p` 前缀、关闭频道后输入框提示、横屏布局（在 812×375 下标签条和输入框不被挤掉）。

## 10. 风险与取舍
- **串频道 = 隐私事故**（队伍/群聊的话出现在公屏里）：靠"服务器按频道解析接收人"这一个出口 + 集成测试覆盖；协议版本 +1 强制老页面刷新。
- **骚扰**：群聊是最大的新风险（拉陌生人入群刷屏）→ 只能好友互拉、需要对方接受、数量/限频、可退出、可屏蔽、可举报。
- **记录膨胀**：队伍/群聊记录只追加不删；按现在的体量（几百人）完全没问题，以后可以做"保留 N 天"的清理。
- **小屏占位**：频道条会占一行，横屏已经很矮——标签条可以横向滑动、收起时只显示当前频道名。
- **管理员工作量**：群聊越多越难管，所以「按群/成员搜」「被举报多的群标红」放进 P2，而不是以后补。

## 11. 已拍板的决定（2026-11-05）
1. **分期**：**先做 P1，再做 P2**（P3 视反馈）。
2. **群聊拉人**：**只能好友互拉**，对方接受才入群；不做邀请码、不做公开搜索（P3 再议）；规模按 §5 的建议值（每群 20 人、每人建 3 个 / 加入 10 个）。
3. **管理员看群聊记录**：**站长可查（每次写审计），协管员只能看举报附带的证据**。
4. **「关闭频道」**：**关闭 = 服务器不再下发、也不能在里面发言；另有「静音」**（还收，只留未读数）。

**以下三项没单独问，先按建议值定，不合适随时改：**
5. 个人世界里队伍 / 群聊照常能聊（世界频道仍只回显自己）。
6. 群聊记录永久保存；新成员只能看到加入之后的消息。
7. 系统提示拆到独立的「系统」标签，不再混在世界里。
