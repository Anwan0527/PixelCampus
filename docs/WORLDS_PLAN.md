# 个人世界 / 好友世界 / 公共世界 方案（2026-11-05；一期「公共/个人世界」已实现，见 CHANGELOG）

> 一期实现时按本文的建议定了各项：个人世界里可以输入、只回显给自己并提示一次；登录默认世界可设置（默认公共）；个人世界的公屏记录也存（带世界标记）；个人世界回公共世界/下线就收掉。二期好友世界已按本文建议实现（房主 + 最多 6 位好友、只有房主能邀请、好友可申请加入、房主离开即解散、可设「不接受申请」）；管理员世界页（三期）已实现（2026-11-05，见 CHANGELOG）：列出所有世界、隐身/现身进入、离开、记审计、公屏记录按世界筛选；另外加了玩家举报功能。

> 目标：让玩家自己选择"和谁一起玩"——**一个人安静地玩**、**只和邀请的好友玩**、或者**进入热闹的公共校园**；管理员能看到所有世界并进入处理问题。
> 这份文档只是方案，还没有写代码；末尾「需要你拍板的事」定下来后再开工。

## 1. 三种世界

| | 谁在里面 | 能看到谁 | 公屏 | 创建/结束 |
|---|---|---|---|---|
| **公共世界** | 所有选择公共世界的人（默认） | 公共世界里的所有人 | 所有人的消息 | 一直存在 |
| **个人世界** | 只有自己 | 谁也看不到，也没人看得到你 | 看不到别人的话；**只有系统提示和好友提示**（好友上线、好友私信/申请等）；自己说的话只回显给自己 | 选了就有；回公共世界或下线就结束 |
| **好友世界** | 房主 + 房主邀请且接受的好友 | 房主和受邀好友 | 只有这几个人的消息（外加系统提示、好友提示） | 房主创建；**房主离开 = 世界解散，成员回到公共世界** |

- 三种世界用的是**同一张校园地图**：切换世界时人的位置不变，只是"同一个地方的其他人"换了一批。这样不用搬人、不用重新生成地图。
- 世界是**服务器内存里的概念**，不写进地图数据；玩家的档案（背包、精灵、好友、宿舍…）不受影响，在哪个世界都是同一份。

## 2. 服务器怎么改（核心：给每个玩家一个"当前世界"）

### 2.1 数据模型
- 新增 `server/worlds.ts`：`World { id, kind: 'public' | 'solo' | 'group', owner(校园号), members, since, dropped(留在地上的共享单车), catFollowers/catAway(被人带着走的小猫) }`。
- `Player.w`（所在世界）。登录默认进公共世界；`Saved.wm`（可选）记住"登录时默认进哪个世界"（公共/个人），好友世界不记。
- 现有的**宿舍**（`Player.room`）是独立的小空间，与世界无关：宿舍里的人本来就从世界里隐身，出宿舍回到原来的世界。

### 2.2 哪些东西要按世界隔离（全部盘点过了）
现在服务器里"全服共享"的东西，一旦有了多个世界，必须逐个处理，否则会**串世界**（个人世界里的人被别人看到、消息漏到公屏）：

| 现有逻辑 | 位置 | 处理 |
|---|---|---|
| 看见别人（视野 AOI、`spawn/despawn`、位置快照） | `tick()` 的双层循环 | 加一个条件：`q.w !== p.w` 当作不可见（自然就会发 despawn）。**这一处同时让个人/好友世界里没有别人**；循环还会变便宜 |
| 公屏广播 | `onChat` 里的 `broadcast` | 改成只发给同一个世界的人；`chat_history` 也按世界给（个人世界进去是空的） |
| 公屏撤回、管理员广播 | `chat_recall`、`say` | 撤回：发给消息所在世界；管理员广播/系统提示：**所有世界都发**（"系统提示"不隔离） |
| 小猫被谁带着 `catFollowers/catAway` | 全局 Map | 改成**每个世界一份**；切换世界时，正带着小猫的人先让小猫回家 |
| 留在路边的共享单车 `dropped`、`bike_drop/gone` | 全局 | 改成**每个世界一份**；切换世界时先下车锁车 |
| 手拉手连线 `hand_pairs`、在线人数 `online` | 广播 | 手拉手只发同世界；在线人数分两个数：全服在线 / 当前世界里几人 |
| 好友位置 `sendLocs`、好友上线提示 `friend_on` | 好友系统 | 好友在别的世界时，位置显示"在个人世界/在好友世界"（不泄露坐标）；**好友上线提示不隔离**（需求里明确保留） |
| 组队传送、同骑单车、手拉手、玩家交易、校园跑邀请 | 都要求"离得近/在线" | **必须在同一个世界才能用**；不在同一世界给出提示"TA 在另一个世界里，先加入 TA 的世界" |
| 宿舍做客、好友私聊、好友申请、留言板、校园墙、名人堂 | 与世界无关 | **不隔离**（私聊/申请本来就是点对点；留言板/墙是全服内容） |
| 公屏记录 `chat.jsonl` | 追加写 | 每条加 `w`（世界标记）；个人世界里自己说的话**也记录**（只在管理员查看时可见，和私聊同一套隐私规则，查看进审计） |

### 2.3 切换世界的规则
- **不能切换的状态**：战斗中、交易中、校园跑中、钓鱼中、在宿舍里；骑车/坐着/坐队友车/牵着手时**自动处理**（下车锁车、起身、松手）。
- 切换有 **10 秒冷却**，防止反复开关刷屏、折腾别人的视野。
- 切到个人/好友世界时：对原世界的人我就是"下线了"（despawn），他们在公屏里**不会收到"离开了校园"**之类的提示；回公共世界同理。
- 组队：队伍是玩家之间的关系，不拆；但队友在不同世界时，传送/同骑/看位置不可用，界面显示队友"在另一个世界"。

### 2.4 消息（新增）
- 玩家→服务器：`world_set { kind: 'public' | 'solo' }`、`world_invite { uid }`（房主在自己的好友世界里邀请，没有就先建）、`world_ask`/`world_reply`（好友的接受/拒绝；也可以反过来"申请加入对方的世界"，对方同意才进）、`world_leave`。
- 服务器→玩家：`world_state { kind, owner, ownerName, members: [{uid,name}] }`（进入/成员变化时发）、`world_ask`（弹出接受/拒绝提示条，复用现在宿舍/牵手的提示条）。
- 管理员：`adm_worlds`（所有世界的列表）、`world_enter`、`world_kick`。
- 协议版本 +1。

## 3. 客户端怎么改

- **世界标识条**：左上角头像旁加一个小标签：「🌍 公共世界 · 当前 23 人」/「🏠 个人世界」/「👥 好友世界 · 3 人」，点开是**世界面板**。
- **世界面板**：三个选项（进入公共世界 / 进入个人世界 / 邀请好友一起玩）；好友世界里显示成员，房主可以邀请、踢人、解散；设置项"登录时默认进入：公共/个人"。
- **好友列表**：在线好友一行多一个「邀请一起玩」；好友当前所在世界显示成文字（"在公共世界/个人世界/好友世界"）；好友在个人世界时可以"申请加入"（对方同意才进；个人世界的主人可以在设置里关掉被申请）。
- **切换时的表现**：淡出淡入一下；清空已有的远端玩家（服务器会补发 despawn，客户端再保险清一次）；公屏清空并显示一条系统提示「已进入个人世界：这里只有你，公屏只显示系统和好友提示」；手机端小地图、气泡等跟着刷新。
- **个人世界里发言**：输入框仍可用，但发出去只回显给自己，并提示一次"个人世界里没有别人听得到，想聊天可以回公共世界或邀请好友"。

## 4. 管理员

- 管理面板新增「世界」页：列出**所有世界**——公共世界（人数）、每个个人世界（主人、开始时间）、每个好友世界（房主、成员）；每行有「进入」「踢出这个世界里的人」。
- **进入**：管理员可以选"可见进入"或"隐身观察"（隐身 = 别人看不到管理员、管理员能看到世界里的人和公屏）；进入后看到的就是那个世界的公屏。回自己原来的世界按「离开」。
- **审计**：进入任何世界都记进操作记录（谁、什么时候、进了谁的个人/好友世界、隐身与否）；个人/好友世界里的公屏记录，管理员在"公屏记录"页可以按世界筛选，查看同样记审计。
- 现有的"点名字禁言/撤回/封禁"在各个世界里都能用。

## 5. 玩法与经济上的影响（要明确的）

- **个人世界不会产生"刷"的问题**：背包、精灵遭遇、钓鱼、翻垃圾桶都是**每个玩家自己的**（服务器按个人档案结算），和有没有别人无关；每日上限照旧。
- 需要多人的活动（交易、组队、校园跑对战、同骑）在个人世界里自然没法用；好友世界里可以用。
- 小猫、单车是共享资源：个人世界里这两样都是"你自己的一份"，不会和公共世界互相抢。
- 名人堂、留言板、校园墙、公告：全服共享，不分世界。

## 6. 分期

| 期 | 内容 | 说明 |
|---|---|---|
| **一期** | 世界模型 + **公共/个人世界切换**：视野、公屏、小猫、单车、手拉手、好友位置/提示、切换限制与冷却、客户端标识条和世界面板、默认世界设置、测试 | 做完就能满足需求 1 和 3；是最大的一块（改动面在"广播/共享状态"） |
| **二期** | **好友世界**：邀请/申请/接受、成员管理、房主离开解散、成员数上限 | 复用宿舍做客的邀请/接受提示条和流程，工作量中等 |
| **三期** | **管理员世界页**：世界列表、进入（可见/隐身）、踢人、审计、公屏记录按世界筛选 | 依赖一、二期 |
| 以后 | 公共世界分线（人太多时自动分成几条线）、世界邀请码 | 现在不做，数据结构已经为它留好（`World.kind` 可扩展） |

## 7. 风险与测试重点

- **最大风险是"串世界"**：个人世界的消息/人漏到公共世界（隐私问题）。对策：把所有 `broadcast` 改成必须显式指定范围（全服/某个世界），不留"默认全服"的口子；每个广播点都有联机测试：**两个世界各有人，互相收不到对方的聊天、位置、撤回、单车、小猫**。
- 其次是**状态残留**：切换世界时骑车、牵手、带猫、组队传送、宿舍里这些状态的收尾（每个都有测试）。
- 兼容：旧页面不认识新消息（协议版本 +1，刷新即可）；服务器重启后世界全部重置为公共世界（个人/好友世界本来就不持久）。
- 性能：几乎没有额外开销；视野循环按世界过滤后反而更快。
- 回滚：新增的只有 `Saved.wm`（默认世界）一个字段，旧版本会丢掉它，影响很小。

## 8. 需要你拍板的事

1. **好友世界的人数上限**：我建议和宿舍一致，**房主 + 最多 6 位好友**。
2. **谁能邀请**：只有房主能邀请，成员不能再拉人？（我建议只有房主；好友也可以"申请加入"房主的世界，房主同意才进）
3. **登录时默认进入哪个世界**：我建议做成可设置、默认公共世界；选了"个人世界"的人下次登录直接进个人世界。
4. **个人世界里发言**：我建议"可以输入、只回显给自己、第一次提示一下"；也可以改成直接禁用输入框。
5. **个人/好友世界的公屏要不要记录给管理员查**：我建议**记**（防止有人借私人世界违规），查看要进审计，和私聊同一规则；如果你想更强的隐私，也可以不记。
6. **管理员进入别人的世界**：我建议提供"可见进入 / 隐身观察"两种，且**全部记审计**；要不要让被进入的玩家收到提示（"管理员进入了你的世界"）？隐身观察时我建议**不提示**，否则没法处理违规。
7. **好友在个人世界时，别的好友能不能申请加入**：我建议默认允许申请、对方同意才进，并给个人世界的主人一个"不接受申请"的开关。
8. **公共世界里有没有人数上限**：目前服务器总上限 200 人。你想不想以后做"分线"（人太多自动分成几条线）？一期先不做。
