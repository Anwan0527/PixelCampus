## 1. 背景与目标
- **问题**：玩家的身份是浏览器 `localStorage` 里的随机 token，**每个域名一份**。`exist.qd.je` 上的老玩家第一次打开 `huepixel.top` 会是「新生报到」（新档案），原来的角色、好友、背包、小猫都看不到。
- **主人想要**：慢慢迁移；**暂时两个域名都能玩**，以后只开放备案好的；老玩家在新域名上仍然是自己（同一个校园号、角色、好友、背包）。
- **目标**：
  1. 老玩家在 `exist.qd.je` 上点一下，就带着身份到 `huepixel.top`，进去还是自己（不需要手抄备份码）。
  2. 迁移后**两个域名都能用同一个身份**（同一个游戏世界、同一份存档，不是复制一份）。
  3. 迁移过程中 token **不出现在网址、浏览器历史和服务器日志里**。
  4. 后期能平滑切到「只开放新域名」（旧域名只剩一个「请去新网址」的页面，一键迁移仍可用）。
- **非目标**：不合并两个域名上不同的账号（见 R6）；不迁移纯本机的小设置（音量、旁白已读等，丢了就重新设置）；不做账号密码体系。

## 2. 方案（推荐）
**服务器发一次性「搬家券」**（和现有的备份码恢复同一类、同样在 `hello` 之前的临时连接里完成）：
1. **老域名页面**点「搬到新网址」→ 临时连一次服务器，发 `migrate_make { token }` → 服务器校验这个 token 是已存在的身份，返回一张**搬家券**（192 位随机、3 分钟内有效、只能用一次）。
2. 页面跳到 `https://huepixel.top/pixel/#m=<搬家券>`（**券放在 `#` 后面，不会发给服务器、不进 nginx 日志；券本身不是身份**）。
3. **新域名页面**启动时发现 `#m=`，立刻把它从地址栏抹掉，临时连一次服务器发 `migrate_claim { ticket }` → 服务器核对、**立刻作废这张券**，把 token 和学生证资料回给这个浏览器 → 客户端存进本机（`setToken` + `saveProfile`）→ 刷新进游戏。
4. 之后新域名里这个浏览器的 token 和老域名的**是同一个**，所以两边登录的是同一个角色。

**为什么不用别的办法**：
- *直接把 token / 备份码放进网址*：会留在浏览器历史、可能被同步 / 截图 / 转发；
- *用隐藏 iframe 去读老域名的 localStorage*：现代浏览器对跨站 iframe 的存储做了分区，读不到（Safari / Chrome / Firefox 都是）；
- *让玩家手抄备份码*：能用（已有，作为兜底保留），但对手机玩家很不友好。

**服务器会短暂地在内存里保存 token**（≤ 3 分钟、用完即删、重启即丢、不写盘、不进日志）——这是为了能把 token 交给新域名；服务器平时只存 token 的哈希。

## 4. 规则与边界
- 一个身份对应一个 token；迁移是**共享**不是复制：两个域名上同时在线算同一个玩家（服务器按 token 识别，同一身份同时登录两处，沿用现有的「顶号」规则）。
- 券绑定的是某个已存在的档案；服务器上不存在的 token 不发券。
- 搬家券用错 / 过期 / 已用：统一回「搬家券已失效，请回到旧网址重新点一次」。

## 5. 安全
- 券在 `#` 后面：浏览器不会把它发给任何服务器，也不会写进 `Referer`；新页面读到后立刻 `history.replaceState` 抹掉。
- 券本身不能直接当身份用（只能换一次 token，3 分钟内，每 IP 限频），拿到网址的人如果在 3 分钟内抢先打开，会得到这个身份——风险和「3 分钟内把备份码发给别人」同级；界面文案提醒「别把这个链接发给别人」。
- 服务器内存里临时保存的 token：上限 500 张、3 分钟过期、清理在每次 make / claim 时顺带做；不写盘、不进日志（日志只写昵称和 IP，和 restore 一致）。
- 玩家可见文字一律 `textContent`。

## 6. 数据与协议
- 新增（`src/shared/protocol.ts`，additive，`PROTOCOL_VERSION` 不升）：C→S `migrate_make { token }`、`migrate_claim { ticket }`；S→C `migrate_ticket { ok, ticket?, ms?, msg? }`、`migrate_claimed { ok, token?, profile?, msg? }`。
- **不改存档**，不动 `players.json`。
- 服务端仓库一起改（`server/game.ts` 邻近 `onRestore` 处加一个小模块；新增测试）；公开仓库：`src/shared`（协议 + 券格式校验）、`src/net/migrate.ts`、`src/ui/MigrateBanner.ts`（入口与提示）、启动流程里的 `#m=` 处理。

## 7. 验收标准
- [ ] A1：老域名（模拟）点入口 → 跳转地址是 `https://huepixel.top/pixel/#m=<券>`，且不含 token 或备份码。
- [ ] A2：新域名收到券 → 地址栏立刻不再有 `#m=`；刷新后进游戏，昵称 / 校园号 / 背包 / 好友与老域名一致。
- [ ] A3：同一张券第二次使用失败；3 分钟后失败；不存在的 token 发不出券。
- [ ] A4：每 IP 限频生效；券表不会无限增长。
- [ ] A5：新域名已有角色时弹确认，取消不替换，确认才替换。
- [ ] A6：迁移后老域名仍能正常登录同一个角色。
- [ ] A7：服务端日志里没有 token / 券的明文。
- [ ] A8：`npx vitest run`（公开 + 服务端）与 `tsc` 全绿；真机（手机）走一遍。
