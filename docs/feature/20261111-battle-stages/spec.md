## 1. 背景与目标

承接 #5（技能更换 / 战斗信息 / 结算页 / 快进）。当前引擎只有直接伤害，没有能力等级。

目标：

- 让「能力等级」在战斗里真正生效（攻/防/特攻/特防/速度），玩家能看见。
- 为后续 #6 的「状态异常」「非伤害招式」打好战斗内状态的基础。
- 纯共享规则 + 客户端界面；不改协议、不改存档、不加客户端消息。

## 2. 范围

### 本期做

- `Move.stat` 字段：`{ k: StatKey | 'acc' | 'eva'; d: 1..6 或 -1..-6; target: 'self' | 'foe'; chance?: number }`
- `Battle` 内能力等级（按精灵 id 记，六项 + 命中 + 闪避，±6）
- 伤害公式使用攻/防/特攻/特防倍率；先手顺序使用速度倍率
- `BEvent` 增加 `stage` 事件（谁、哪项、变化、当前值）
- 战斗 UI 显示双方能力等级升降；战斗日志写一句
- 现有技能表挑选几个招式附带 `stat`（例如老吴咆哮降对方攻击），不新增纯变化招式

### 本期不做

- 状态异常（毒/灼伤/麻痹/睡眠/冰冻）
- 纯变化招式（剑舞、叫声、守住、回复）
- 命中/闪避接入命中判定
- 天气 / 场地
- 任何协议 / 存档改动

## 3. 正向场景

- **P1.** 使用带 `stat` 的伤害招式命中后，目标（或自己）对应能力等级按 `d` 变化，事件里带上变化后的值。
- **P2.** 攻击等级 +2 的精灵用物理技能，伤害约为 0 级时的 2 倍（其余条件相同）。
- **P3.** 防御等级 +2 的目标受到的物理伤害约为一半。
- **P4.** 特攻 / 特防对特殊技能同理。
- **P5.** 速度等级更高的一方的先手判断按倍率后的速度比较。
- **P6.** 能力等级最多 ±6，超出部分截断。
- **P7.** 精灵 A 被降防后换下，再换上来时仍带着原来的降防等级。
- **P8.** 精灵倒下时，它的能力等级清零（再上场是 0）。
- **P9.** UI：双方卡片下方显示「攻击 +2」「防御 −1」等；没有变化的项不显示。
- **P10.** 战斗日志出现「XX 的攻击提升了！」「XX 的防御降低了！」等文字。
- **P11.** 战斗结束后能力等级随 `Battle` 丢弃，不影响下一场。

## 4. 反向 / 异常场景

- **N1.** 能力等级**绝不能**超过 ±6 或低于 −6。
- **N2.** 能力等级**绝不能**写进 `Mon` 存档（`cleanMon` 前后一致，旧存档不需要迁移）。
- **N3.** 本期**绝不能**新增客户端消息、改 `protocol.ts` 或要求服务端改存档。
- **N4.** 命中/闪避等级**绝不能**在本期影响命中判定（`attack()` 的 `rnd()*100 >= m.acc` 不变）。
- **N5.** 没有 `stat` 的招式**绝不能**产生 `stage` 事件。
- **N6.** `chance` 未命中时**绝不能**改能力等级，但招式本身照常结算伤害。
- **N7.** 换人**绝不能**把下一位精灵的能力等级清零（除非它自己倒下过）。
- **N8.** 倒下的精灵**绝不能**保留能力等级再上场。
- **N9.** 相同随机序列 + 相同行动**绝不能**出现不同结果（确定性）。
- **N10.** 旧存档 / 没有 `stat` 的内容包**绝不能**报错，按无效果处理。
- **N11.** 玩家可见文字**绝不能**用 `innerHTML`。
- **N12.** 战斗 UI 中能力等级**绝不能**只靠颜色区分（必须有文字 / 箭头）。

## 5. 数据 / 协议

- `Move` 增加可选 `stat`；内容包里可以携带，缺省不影响旧数据。
- `Battle` 增加内部能力等级存储（不导出到 `Mon`）。
- `BEvent` 增加 `{ t: 'stage'; side; k; d; v }`。
- **不改 `protocol.ts`、不改 `mon_data` / `mon_bt` 字段形状（`sq` 仍是 `Mon[]`）。**

## 6. 界面与交互

- 战斗卡片下方加一行 `.bt-stages`：`攻击 +2`、`特攻 −1`…
- 没有变化的项不显示；全部为 0 时不显示这一行。
- 战斗日志：`xx 的攻击提升了！`（+1）、`大幅提升了！`（+2 及以上）、`降低了！`（-1）、`大幅降低了！`（-2 及以下）。
