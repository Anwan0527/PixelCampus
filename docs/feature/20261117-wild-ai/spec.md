# IR #11 · 野生 / 校园猫对战 AI 需求规格

> 对应 Issue：[EXIST-D/PixelCampus#11](https://github.com/EXIST-D/PixelCampus/issues/11)
> 规范：[docs/feature/spec.md](../spec.md)
> 状态：已确认、已实现（2026-11-17）
> 关联：Issue #11（精灵对战 3D 的 AI 部分；PvP 部分已随 #28 上线）、[trainer-npc](../20261113-trainer-npc/spec.md)（训练家 AI 已实现，本批复用）

## 1. 背景与目标

**现状**：野生精灵和校园猫出招是**纯随机**——`src/shared/battle.ts` 的 `wildMove()` 在当前招式中等概率抽一个，不看属性、不看血量、不看 PP。训练家对战已经有 `aiChooseMove()`（60% 概率选克制招），但野外和猫战没用上，打起来像在和骰子对打。

**目标**（可验证）：

1. 野生精灵 / 校园猫会按**属性克制、威力、命中、PP、自身血量、对手已有状态**选招；
2. 有**难度分档**：野生温和、校园猫认真、训练家保持现状；
3. 纯 `src/shared/` 纯函数、随机源注入，服务器直接调用；**不改协议、不改存档**；
4. 相同种子下决策可复盘（测试能断言）。

**非目标**（本批不做）：

- 不新增战斗机制（天气、场地、双打）；
- 不动数值表（威力 / 命中 / PP / 属性相克）；
- 不做玩家 PvP（已上线）；
- 不做 AI 换人（野生和猫都只有一只；训练家换人已经在用 `aiWantsSwap`）。

## 2. 用户与场景

- **玩家**：在草地遇敌、和校园猫友谊赛时，对手出招更“像在思考”。
- 典型表现：
  - 对手带着克制你的招 → 更可能用出来；
  - 自己残血而带回复招 → 更可能回复；
  - 你已经中毒了 → 不会再用一次中毒招；
  - 招式 PP 用完 → 不会选它。
- 离线模式（`?offline`）同样生效：AI 在共享规则里，客户端单机战斗也走同一套。

## 3. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| R1 | 野生精灵出招不再纯随机，至少考虑**属性克制与威力** | P0 |
| R2 | 校园猫出招同理，且**比野生更认真** | P0 |
| R3 | 不选对当前对手**倍率为 0** 的招式（除非没有别的可选） | P0 |
| R4 | **不重复施加**对手已经处于的状态（睡眠 / 冰冻 / 中毒 / 灼伤 / 麻痹） | P1 |
| R5 | 自己血量低且带回复招时，**提高回复招权重** | P1 |
| R6 | **PP 为 0** 的招式不选 | P0 |
| R7 | 难度档可配置（野生 / 校园猫 / 训练家各自的“认真程度”） | P1 |
| R8 | 相同随机种子下决策**可复盘** | P0 |

## 4. 规则与数值

- **认真程度**（选“最优招”的概率，其余回合随机）：
  - 野生精灵 **35%**
  - 校园猫 **55%**
  - 训练家 **60%**（保持现状，`aiChooseMove` 已如此）
- **“最优招”的评分**（粗略排序，具体权重在 plan 里定）：
  - 伤害招：`威力 × 属性倍率 × 命中率`；倍率 0 直接排除
  - 回复招：自己血量 ≤ 40% 时加权，血满时排除
  - 状态招：对手已有该状态时排除；对手是免疫该属性的情况排除
  - PP 为 0 排除；只剩一个可用招时直接用它（不再掷骰）
- **不改变任何伤害 / 命中 / PP 数值**，只改变“怎么选”。
- **刷的漏洞**：不涉及经济与奖励，无新增收益。

## 5. 界面与交互

- 无新界面、无新按钮。
- 战斗日志文案不变（仍然是「野生的XX使出了YY！」）。
- 玩家能感知到的只有“对手变聪明了”，不需要任何设置项。

## 6. 数据与协议

- **不改协议**（`src/shared/protocol.ts` 不动）、**不改存档**。
- 改动集中在：
  - `src/shared/battle.ts`：`wildMove()` 改为调用新的选择函数；
  - `src/shared/trainers.ts`：把评分 / 选择抽成可复用的纯函数（训练家现有行为保持不变）；
  - `tests/`：新增 AI 行为测试。
- 服务端不用改（它调用共享规则），但发版时服务端要一起更新依赖。

## 7. 安全、隐私与内容

- 纯函数、无玩家输入、无网络、无存档写入；不涉及敏感词 / 权限 / 审核。

## 8. 性能与成本

- 每回合最多评估 4 个招式，纯算术；对服务器可忽略（训练家战已经在跑同样的逻辑）。

## 9. 验收标准

- [ ] A1：给定玩家为水属性、对手带草 / 一般两个招，固定种子下草招被选中的比例**显著高于随机**（测试断言）。
- [ ] A2：带 0 倍招式时不出（除无其他选择）；测试覆盖。
- [ ] A3：对手已有中毒状态时，不再施加中毒。
- [ ] A4：相同种子两次运行结果完全一致。
- [ ] A5：训练家战行为不变（现有训练家测试仍全绿）。
- [ ] A6：`npm test` / `tsc` / `vite build` 全绿；无新增协议消息。

## 10. 未决问题

- [ ] **野生要不要变强**：建议 35%（只是“偶尔聪明”，新手不至于被反复压制）；也可以先上 25%。
- [ ] **校园猫 55%** 是否合适？（猫战是友谊赛，太强会劝退）
- [ ] **训练家维持 60%** 不动，对吗？
- [ ] AI 用**回复招**时要不要考虑“对手下一招可能秒我”（本批不做预判，只看当前血量）。
